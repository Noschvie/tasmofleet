# Navigation and in-page patterns (proposal)

Prototype for porting into the app (`internal/web`) and into `styles.css` via the code repo + `/design-sync`. The synced DS files are untouched.

**Built on the app's markup.** The four templates are the output of `layout.html`, `partials.html` and the page templates (plus the Columns menu that `tableprefs.go` writes), filled with sample data. They use the app's ids, `data-*` hooks and class names, and they run the app's own scripts. So the port is a CSS and markup diff, written up in **`PORT.md`**.

- `patterns.css`: the only new CSS, loaded after `../../styles.css`. Uses only existing tokens. Every new class is listed in the block at its top.
- `Patterns.html`: component page for the 7 patterns plus the QA v0.9.0 decisions (sections 8–13); resize under 768px (48rem) / 960px (60rem) for phone and narrow variants.
- `Screens.html`: screen-level fixes from `QA-FINDINGS.md` (device that never answered, backups, replace, discovery, options, console, policy, rules editor, audit, account, setup).
- `Reference.html`: Patterns, Screens and the four templates at 1280 and 375, light and dark.
- `Dashboard.html`, `Devices.html`, `Device.html`, `Firmware.html`: the four templates using the patterns (app markup + the proposed diff).
- `PORT.md`: the diff per app file (layout.html, partials.html, device.html, firmware.html, devices.html, tableprefs.go, menu.js), plus the server items.
- `static/`: copies of the app's `select.js`, `jump.js`, `dialog.js` (unchanged) and `menu.js` (one proposed line, marked PROPOSED).

## Changed behaviour of existing classes

- `header.top`: `.mainnav` and `.user` get `.d-only`; Sign out moves into the user menu (local: Change password; SSO: `.menu-note`). Focus ring is drawn inset on `.navtop`.
- `.jump` keeps the app markup (`div.jump[hidden]` + `select[data-jump]`, shown and wired by jump.js). Without JS the tabs stay and wrap.
- `td.rowacts`: shrink-to-fit, vertically centred. `.table-scroll` stops clipping while a row menu is open.
- `.bulkbar`: fixed to the viewport (not sticky in the form); count + Clear stay on the left, actions on the right. On phones it spans the full width, one row high, and respects the safe area.
- `details.fold` / `.m-fold`: the chevron follows the title; `.meta` goes to the right.
- `.card`: top padding = title height + 0.75rem (40px hit area / 2 + 0.75rem on phones). Framed fold titles get a 40px hit area.
- Templates: every action is a `button`. Destructive ones carry `data-dialog` (dialog.js opens the dialog) and `formaction` + `formmethod="get"` to the confirmation page as the no-JS fallback. Links only navigate (Download, Restore…, Start update… lead to pages). Firmware cached files: "Needed by" and "Installed on" are labelled lines inside the row card on phones, and the row action is in `td.rowacts`.

## Open points

- `text-box` (#8) is progressive: browsers without it keep today's centring.
- Proxy-header accounts: the app has to tell the template which kind of account is signed in (local, SSO, header).

- Phone breakpoint: 48rem everywhere (styles.css re-synced, patterns.css and the pages follow).
- Server work (PORT.md): **now**: device delete confirmation page, proxy-header accounts as a third kind (display only), device Restart, bulk Send command. **Later**: bulk Back up / Restart, the Scan / Discovered split. The design keeps the later controls; until the server has them the templates leave them out.
- Rows that need `.rowmenu.up`: the server marks the last two rows of a table.
