# tasmofleet — QA findings for the design pass (v0.9.0)

From the visual QA of the live app.
These are the findings that need a design decision. Address them in the nav-patterns
prototype (templates/nav-patterns/), using existing tokens; add new classes to the
port block at the top of patterns.css. For each finding, note in README.md how the
prototype solves it (or why it is dropped).

- #3 [Cross-cutting; 1280 light+dark, Columns menu open; Minor; defect] The "Show or hide columns" tooltip stays open over the open Columns menu, covering its heading and the first row's arrows, and sticks out about 16px past the card. A glyph of "Last restart (" is clipped at the menu's right edge.
  Status: deferred v0.9.0 (clipped glyph in the Columns menu needs browser-side debugging, no layout fix that is safe to guess)
- #7 [Cross-cutting; 375 light+dark; 1280 toolbars; Minor; defect] (reviewer) Inconsistent button sizes. At 375, "Refresh index" is auto-width while "Show 7 older releases" (a `label.button.sm`) stretches across the card. Both are 40px tall there. At 1280 the toolbar buttons (Refresh index, Select unused, Select none) are about 28px tall, and the default buttons beside them 38px. The audit pager buttons are shorter than the "Per page" buttons. Fix: one height per size, one size per toolbar (draft §3.5, guard e).
  Status: deferred v0.9.0 (one button height per toolbar is a cross-page sizing change with design impact)
- #8 [Cross-cutting; 375+1280 light+dark; Minor; defect] Labels are not vertically centred in their box. "Show 7 older releases" sits about 7px high (the label has no flex centring), the On/Off power toggle text about 4px high at 375 (its dot sits lower), the status pills ride slightly high, and the active "Dashboard" nav pill has its text near the top. Guard c.
  Status: deferred v0.9.0 (vertical centring of the toggle, pills and nav is a cross-page typography change)
- #9 [Cross-cutting; 375 light+dark, every page; Minor; defect] Top navigation at 375: "Dashboard" (a link) sits 3 to 4px higher than the Devices, Updates and System summaries. The nav items are about 30px tall, under the 40px touch target. "admin" is dropped and the account trigger crowds "Sign out".
  Status: deferred v0.9.0 (phone top bar rework (nav height, account trigger) has design impact)
- #13 [Cross-cutting; 375 light+dark; all pages; Minor; defect] Touch targets under 40px at 375: row checkboxes (18px hit area in some tables), "Download" text links (about 20px), crumbs and "Compare and restore" (about 18px), the Cancel link on confirm pages, "Not checked" rows on /policy (about 31px). The existing `smallTargets` guard exempts prose and crumb links; extend it to links that act as row or form actions.
  Status: deferred v0.9.0 (extending the smallTargets guard to row-action links touches many pages)
- #18 [Cross-cutting; all; Minor; design] (reviewer) Four sub-navigation patterns: tabs (Add devices), a side list (System settings), jump pills (Device settings), and header buttons (device: Console, Settings, Edit, Replace; Policy and Policy rules link each other through buttons). On phones some become a select and some do not. One tab component (draft §3.8).
- #19 [Cross-cutting; all; Minor; design] Links and buttons are mixed for the same kind of action: "Download" is a link next to "Restore" and "Delete" buttons, "changes" is a link stacked on a "Revert to this" button, "Compare and restore" is a link under the "Back up now" button, "Show ignored" is a link, and "Cancel" is a link 4px from a button. Links only navigate (draft §3.9).
- #20 [Cross-cutting; all; Minor; design] Bulk actions in three shapes. On /devices the desktop has an inline toolbar ("Switch on selected"), the bulk bar uses other labels ("Switch on") and only appears on phones. /policy has an inline "Make selected compliant" (missing at 375). /firmware has an inline "Delete selected". One shared bulk bar (draft §3.11).
- #21 [Cross-cutting; all; Minor; design] (reviewer) Row actions differ per table and per width: direct buttons on desktop and an Actions menu on phones for the same actions (firmware releases, policy rules), a "Manage" menu at all widths (users), and direct buttons (backups, discovery). At most 2 direct buttons, otherwise one Actions menu in a fixed place (draft §3.10).
- #22 [Cross-cutting; all; Minor; design] Empty states use four patterns (a bold title with a hint, one line pointing to a header button, a bare line, a free paragraph), placed differently, and none carries the action that fills it. Empty tables keep enabled controls (Select all shown, Export JSON, Check all devices now, column chooser).
- #23 [Cross-cutting; all; Minor; design] Confirmations take three forms: the browser's native `confirm()` (`hx-confirm`: delete device, cancel transaction, delete backup), a confirmation page (delete file, prune, restore, replace), and `dialog.dlg` (release details). On the pages, the confirming button is neutral ("Delete file", "Restore now", "Replace now") although the trigger was danger or primary, and the facts list is an unstyled `dl`.
- #24 [Cross-cutting; all; Polish; design] Status glyphs: the error alerts use a letter-like "X" that reads as a dismiss button, and the badges use "→ newest" and "→ New device".
- #29 [Firmware; 1280 light+dark; Minor; defect] The Cached files table is about 30px wider than the card's content box. Its right border runs about 9px past the card border, and the "Delete…" buttons end right at the card edge. It needs the `.table-scroll` wrapper or fewer fixed widths.
  Status: deferred v0.9.0 (the scroll wrapper vs card edge needs a layout decision)
- #34 [Firmware; 375+1280, release detail; Polish; defect] The "Used by" lists break before the comma (lines start with ", plug-4m"), and "No file needed for" splits "mystery-/chip".
  Status: deferred v0.9.0 (nowrap for device names collides with the 40px link rule from finding 84)
- #37 [Firmware; 375 vs 1280, operator; Polish; design] At 375 an Actions menu appears per release row, and for operators it holds a single item ("Changelog and fleet") that duplicates the release link. Seven releases hide behind a toggle that the desktop does not have.
- #40 [Transactions; all, logs expanded; Minor; defect] The lamp-1m log box cuts its last line in half, with no fade or scroll hint. The workshop log box has a large empty area (fixed height). At 375 wrapped log lines have no hanging indent.
  Status: deferred v0.9.0 (log box fade and hanging indent are a visual redesign of the log view)
- #50 [Device detail; all; Minor; design] A device that never answered still offers "Back up now" (primary), Console and Settings as active. The Transactions section is missing, while Backups shows a dashed "No backups yet." box.
- #51 [Device detail; 1280; Polish; design] Empty cells are blank in Transactions "Error" and Health "Detail", while the other tables use "-". A column chooser is shown above one-row tables.
- #52 [Device backups; 375; all; Polish; defect] In the phone cards "Restore" floats mid-card and "Delete" at the right. The "→ newest" row has no label, and the hint next to "Review…" wraps under the button. "decoder outdated" has no explanation, "(see About)" is not a link, and the date input shows "mm/dd/yyyy" while the app shows ISO dates.
  Status: deferred v0.9.0 (phone card layout of the backups list needs design work)
- #55 [Restore; 1280 light+dark; all; Minor; defect] At 1280 the confirmation checkbox (restore, replace, "Reset to default on save") sits alone on its own line above its label. At 375 it sits inline. The second advisory on the restore page starts in lowercase.
  Status: deferred v0.9.0 (confirmation checkbox layout is shared by four pages, design impact)
- #59 [Replace; all; Minor; design] The page does not say up front that the old device still answers (it only refuses after the new address is entered). The address form is a half-width card inside a card (double frame), the "did not answer" error sits above the intro, far from the fields. In the preview, the backup form is another nested card and the boxes have different widths.
- #60 [Discovery; 375; 1280; Minor; defect] At 375 the hit cards show "Actions" with an empty value, "not in the inventory" on the next line right-aligned, and the buttons left-aligned below. At 1280 the Actions column has no header and its text is stacked above the buttons. The gap between "HTTP scan" and "Proposals" is 43px (22px elsewhere), and "Start scan" is enabled without device networks.
  Status: deferred v0.9.0 (discovery hit card layout needs design work)
- #61 [Device settings; 1280; Polish; defect] In the Options card, labels such as "SetOption0 (save_state)" wrap to two lines and the (i) sits in a separate column. In General it follows the label inline.
  Status: deferred v0.9.0 (Options label/(i) grid change has design impact)
- #62 [Device console; all; Polish; design] The "Command" card has no legend, the "History" card has one.
- #65 [Policy rules; 1280+375, editor; Minor; defect] The Devices chip list is a fixed-height scroll box that cuts the last row of chips in half (no fade, no visible scrollbar). At 375 inputs and selects clip their text with no ellipsis, and the "Note" fold title is followed by a field label "Note".
  Status: deferred v0.9.0 (chip list scroll box needs a design decision)
- #67 [Policy; 375 light+dark; Minor; defect] Device rows at 375: names are clipped without ellipsis ("workshop-ceiling-sp", "Mr Bambu External Ligh"), and rows without a checkbox start further left than rows with one. Opening a device fold moves the badge under the name and the checkbox to the middle of the block (a checkbox not centred in its row line). The "1 to fix" badge ignores the unknown findings (mystery-chip has 3). "Make selected compliant" is hidden at 375 while the checkboxes are shown.
  Status: deferred v0.9.0 (policy phone rows need a layout rework)
- #70 [Audit; 1280; 375; Minor; defect] At 1280 "When" truncates to "2026-10-20 16:3…" and targets are cut while Summary has about 350px free; the "! refused" pill wraps onto two lines. At 375 the cards clip hard with no ellipsis ("Systen", "transa", "ada…"), which leaves rows unreadable.
  Status: deferred v0.9.0 (audit phone cards need a layout rework)
- #71 [Audit; 1280, tooltip; empty filter; Polish; defect] The JSON tooltip covers rows 2 to 4 (see finding 1 for its dark-mode edge), and wrapped JSON lines start at column 0. With an empty result the filter bar changes its layout (the Action select shrinks), there is no "Clear filter", and the pager shows "Page 1 of 1" for 0 events. The pager has different controls at 375 and 1280.
  Status: deferred v0.9.0 (the pager says "No events" for an empty result (eff8971); the filter bar shrink and Clear filter remain; recheck: partial fix verified; the filter bar no longer shrinks and "Clear the filter" is shown as well; the tooltip and the pager difference were not rechecked)
- #74 [Account; all; Minor; design] For header principals the account dropdown holds only a static note, while "Sign out" is a separate button: a menu that leads nowhere. The forced password change has no way out (no Sign out).
- #75 [Navigation; 1280; Polish; design] Dropdowns align differently (Devices and Updates left, System right). The item order differs: Devices lists the list first, Updates the action first ("New transaction").
- #79 [Setup; all; Minor; defect] Step 4 says "Save the device networks first." while the networks are prefilled and "Finish the setup" is enabled. Step 1 lacks "(optional)", although the intro calls all four steps optional. "Finish the setup" is inside step 4 at 1280 and in a sticky footer at 375.
  Status: deferred v0.9.0 (step 4 is marked optional (eff8971); the Save-networks wording and the footer position remain; recheck: partial fix verified (every step is marked optional))
- #84 [Firmware; 375 light+dark; Minor; defect] The "Used by" cells of "Files this fleet needs" now have a 40px line pitch (the touch-target rule for links in cells), so each device name sits on its own sparse line.
  Status: deferred v0.9.0 (the 40px touch rule for links conflicts with dense lists; needs a decision, not a guess)
