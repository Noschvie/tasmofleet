# tasmofleet DS

> **Historical.** This is the v1 design system. The app follows design v2 since the port
> (design v2): the source is `design/v2/`, the contract
> `docs/spec/design-system.md`. Nothing here is kept in step with the app any more.

The design system for tasmofleet, the Tasmota fleet manager. It keeps the structure of
Claude Design's **Modernist** system (flat surfaces, 0 radius, strong 2px section rules, a
modular grid, Archivo only, mostly ink on ground with an accent used sparingly) and adapts it
for a dense admin UI with **light and dark as first-class themes**.

- `styles.css` is the single source: tokens and components. Everything else only shows it.
- Class names are tasmofleet's (`internal/web/static/app.css`) wherever the app already has the
  component, so the app can switch stylesheets without rewriting templates. New classes are
  marked **NEW** below and in the stylesheet.
- No JavaScript is needed. `theme.js` is an optional theme switch for the preview pages.

## Direction

Architectural and quiet. The page is a grid of framed sections: a 2px ink rule opens every card,
the card title sits in that rule like a fieldset legend, hairlines divide the rest. Text is ink on
a cool off-white (light) or a near-black with a trace of teal (dark). Teal is the one accent: the
primary button, the current tab, the selection bar, links and focus. Status has its own five
roles and always comes as glyph + word + colour. Nothing is rounded, nothing floats except
overlays, which sit one step above the page with a visible border and a shadow in both themes.

### Do

- Show the grid: align to the 12 columns, keep 4px spacing steps.
- Open sections with the 2px rule; put card titles in the frame.
- One primary button per view region; secondary actions as default buttons, more than two in a
  "More" / "Actions" menu.
- Center labels in compact and in-table buttons; keep one fixed height per button size.
- Pair every status colour with its glyph and word.
- Use the overlay surface (border + shadow) for every menu, tooltip, popover, dialog and bulk bar.

### Don't

- Round corners (the only circles are icon shapes: the (i) button and the spinner).
- Use the accent for status, or red for anything but danger.
- Soften the section rules to hairlines, or drop the overlay border in dark mode.
- Put explanations into labels: labels are ≤ 6 words, explanations go into the (i) tooltip.
- List data in tooltips (one or two sentences, ≤ 160 characters).

## Themes

Default: `prefers-color-scheme`. `data-theme="light"` or `data-theme="dark"` on `<html>`
overrides it. Both themes define the same token names, so components never branch on the theme.

Dark is tuned, not inverted: ground `#0c1110`, surface `#131918`, surface-2 `#19201f`, overlay
`#222929` (one step above the surface), hairlines `#313a39`, control borders `#6d7776`.
Elevation in dark comes from the hairline border plus ambient darkness (`--shadow-lg` is a
large, dense black shadow with a 1px dark ring), never from a lighter glow.

## Tokens

All ramps are OKLCH on one shared lightness scale (100 = L 0.97 … 900 = L 0.32, 950 = L 0.245),
so step N of every ramp has the same perceived lightness. Generated by `tools/ramps.py`.

## Adaptation notes vs Modernist

| Modernist | tasmofleet DS | Why |
|---|---|---|
| Accent `#ec3013` (red) + `accent-2` | Teal `#0f766e` (light) / `#2dd4bf` (dark), full OKLCH ramp; no second accent | brand colour; red is reserved for the danger status |
| Light only | Light and dark, same token names, `data-theme` override | requirement |
| Neutral grey ramp | Neutral ramp with a trace of the teal hue (OKLCH hue 190, chroma ≤ 0.012) | ground and ink sit with the accent |
| Body 15px, h1 42px | Body 14px, small 12–13, table 13, h1 26px | dense admin screens (30+ devices at 1280 px) |
| `@import` Google Fonts | Self-hosted Archivo variable woff2 (latin + latin-ext) | strict CSP, no third-party requests |
| Labels flush left, also in buttons | Centered in compact/in-table buttons; flush left only for `.block` | readability in tables, requirement |
| `.btn` min-height 36 | Fixed heights 28 / 34 / 40; all 40 on phones | one height per size; touch targets |
| `.btn` / `.card` / `.tag` / `.nav` / `.table` / `.dialog` classes | tasmofleet classes (`.button`, `.card`, `.badge`/`.tag`, `.top`, `table.dense`, `dialog.dlg`) | the app keeps its markup; one vocabulary |
| Card = surface block, kicker/title/body | Card = surface with a 2px ink top rule and the title in the frame | the app's legend-style cards, made Modernist by the strong rule |
| Shadows sm/md/lg, used decoratively | Shadows only for overlays (and their dark variants) | flat page; overlays must be delimited |
| No status colours | Five status roles with ramps, soft fills, glyphs | fleet health |
| Tooltip: none | Overlay-surface tooltip (not inverted) | one overlay style in both themes |
| Photography grayscale | No imagery | admin tool |

## Decisions that differ from other sources (please confirm)

These are deliberate picks; the alternative is named so it can be cleaned up or reversed.

1. **Phone breakpoint 640px (40rem)**, app.css and the draft use 768px (48rem). Reason: the
   640 px preview cards then show the desktop components, and 641–768 px tablets get the dense
   table in `.table-scroll`. Impact: the e2e touch-target guard (`smallTargets`) runs at
   `max-width: 48rem`; it must move to 40rem, or the DS goes back to 48rem (the one `@media (max-width: 40rem)` block in
   `tools/styles.src.css`).
2. **Power toggle in ink**, the draft keeps amber (`--toggle-on`). Reason: amber is the warning
   role (Stale); ink on/off is not confused with either the accent or a status. The draft's
   token names are aliased to the ink tokens.
3. **Tooltips on the overlay surface**, the draft allows inverted one-line tooltips. Reason: the
   brief asks for one overlay style; this also removes `--tip-bg`/`--tip-fg`.
4. **Desktop button heights 34 / 28 px**, the draft says 38 / 30. Reason: density; on phones
   both are 40 px as in the draft.
5. **Focus ring 2px** (Modernist), app.css has 3px. Both pass WCAG 2.4.11/2.4.13 with the
   ≥ 3:1 focus colour; switch `outline` width in one rule if 3px is preferred.
6. **Type scale in px** (12/13/14/16/19/26), the draft proposes rem steps around a 16px body.
   The brief's dense scale wins; the draft's `--text-*` names are not aliased because their
   values differ.

Adopted from the draft: overlay border ≥ 3:1, control borders ≥ 3:1, one shadow for overlays,
backdrop, z-index layers, menu items 36 px (40 px on phones), dense rows 44 px, checkbox 18 px
with a 40 px hit area on phones, one chevron style (right end, down/up), collapsed = header only,
at most two row buttons (destructive with others → menu), bulk bar with the primary action last,
device sub-pages as tabs, dialog footer with the primary last.

## Build

```sh
python3 -I tools/build.py       # ds-bundle/styles.css from tools/styles.src.css + ramps + dark tokens + state hooks
python3 -I tools/pages.py       # every preview page and thumbnail.html
python3 -I tools/theme_json.py  # ds-bundle/theme.json
python3 -I tools/contrast.py    # contrast table, fails on a pair below its minimum
node tools/shots.mjs <dir>      # screenshots 1280/375, light/dark; reports page overflow and font loading
```
