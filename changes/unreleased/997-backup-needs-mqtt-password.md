Backups: a device that only MQTT can back up (no answer over HTTP, for example in another LAN) and whose MQTT password is not set or was refused is no longer sent a backup over HTTP that can only time out with "The device took too long to answer". The backup ends at once with "Needs an MQTT password", for Back up now, Retry, Back up selected, Back up all now, the scheduled run (counted as failed, so it stays in the notification) and the backups before an update, of a template job and of Replace. When TasmoFleet knows of no recent HTTP answer, it asks the device once over HTTP (Status 11) first. A device that answers over HTTP keeps backing up over HTTP without the password, and when such a backup fails, the error now also says why MQTT could not take it. The Backups table, the device's Backups tab and the result of a backup transaction link to the device's MQTT password form, and with several such devices the Backups page links to Device MQTT passwords on System › MQTT. A backup transaction's result now shows the same reason sentence as the backup history instead of the internal error text (#997, thanks @Noschvie).
