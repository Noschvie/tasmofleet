section: Changed
---

Backups and restores go over MQTT first, like every other change: a device that is online on TasmoFleet's broker with its own topic and has a usable MQTT password is backed up with FileDownload and restored with FileUpload, also while its HTTP API works. That holds for every backup: scheduled, before an update (also an update over HTTP), manual, bulk, and the backups a restore takes before and after the upload. HTTP carries a backup or restore only when MQTT cannot: no usable MQTT password, the topic not the device's own, MQTT commands of the device going unanswered, or a backup that MQTT provably did not send at all. A backup or restore that sent anything over MQTT never goes on over HTTP. A config dump holds the Wi-Fi, MQTT and web passwords; it is not better protected over HTTP (plain text there too), but over MQTT the broker hands it to every client subscribed to the device's topics, so give the broker an ACL that lets only TasmoFleet and the device read them. The files of a backup still go over HTTP, because Tasmota has no file transfer over MQTT: after a dump over MQTT the files are read over HTTP from the device's address, but only when the device there reports the device's own MAC (asked before the web password is sent), and when HTTP does not answer the backup is kept without them and says so. A restore over MQTT writes the backup's files over HTTP the same way, and says when they were not restored. A restore whose backup changes the device's MQTT connection (topic, prefixes, broker, login, client ID, TLS or its fingerprints, or MQTT off) no longer asks the lockout question while the device's HTTP API answers (checked when the restore starts and again right before the upload); the device's next commands then go over HTTP for a while, and the wait for the restart also asks HTTP, so such a restore no longer ends with "did not restart in time" when the device came back under its new topic. The device page's "How TasmoFleet reaches this device" card and the restore page say which way the backup, the restore and the files go (#607)
