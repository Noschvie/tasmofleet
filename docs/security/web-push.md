# Web Push: key, who receives, removal (#610, #611)

Code: `internal/notify/webpush.go` (VAPID, encryption, the subscription check), `internal/notify/push.go` (sender,
key loading, the test push), `internal/store/webpush.go` (migrations 0049 and 0050), `internal/web/push.go` (subscribe
routes), `internal/web/syspush.go` (the Settings list, test and remove), `internal/web/static/sw.js` and `push.js` (the
browser side, #611), `internal/app/notify.go` and `internal/app/cmdbatch.go` (wiring, the owner check). Design: spec 14.5.

Web Push is the first outbound connection that goes to the browser vendors and not to something the admin
configured: TasmoFleet POSTs each event over HTTPS to the push service of every subscribed browser (Google FCM for
Chrome and Edge on Android, Mozilla autopush, Apple, Microsoft). The push service sees the TasmoFleet server's
address, the time and the size of each push, never its content.

Egress: the sender uses the webhook's HTTP client (ten seconds per attempt, redirects only to the same host) and,
like the webhook, ignores `HTTP_PROXY`/`HTTPS_PROXY`. Web Push therefore needs direct HTTPS egress from the
container to the push services.

Lifecycle: a subscription row ends by unsubscribe, by 404 or 410, by its owner no longer being an admin at an
event, by a VAPID key replace (W2), or by a database restore without it. The outcome columns end with the row.
There is no in-memory state; sends in flight are part of the notification drain at shutdown (5 seconds).

The label (#611, migration 0050) is written when a browser subscribes and ends with its row. The time of the last test is one value in the dispatcher (any subscription), overwritten by the next test and empty after a restart; the test's result text exists only in the answer to the request that asked for it. In the browser, the push subscription and the service worker are the browser's own and end with "Remove" on the row of that browser, or with Subscribe again, which replaces the subscription. A subscription the server deleted meanwhile (404/410, another admin's Remove, a key replace under W2) is found on the next visit to Settings ("Not subscribed any more": the endpoint's hash is not in the list, or the subscription was made for another key) and offered again.

Known limits: the state of "this browser" needs a secure page (it reads the subscription and hashes its endpoint with `crypto.subtle`); over plain HTTP the card explains why, and the list, its test and its remove still work because they go through the server. Delivery with no tab open and the folding of the tab's and the push's notification (same tag) depend on the browser and are checked by hand in a real Chrome or Firefox over HTTPS or localhost; a headless browser has no push service.
