# Web Push: key, who receives, removal (#610)

Code: `internal/notify/webpush.go` (VAPID, encryption, the subscription check), `internal/notify/push.go` (sender,
key loading), `internal/store/webpush.go` (migration 0049), `internal/web/push.go` (routes),
`internal/app/notify.go` and `internal/app/cmdbatch.go` (wiring, the owner check). Design: spec 14.5. The browser
side (service worker, subscribe button, Settings list) is #611.

Web Push is the first outbound connection that goes to the browser vendors and not to something the admin
configured: TasmoFleet POSTs each event over HTTPS to the push service of every subscribed browser (Google FCM for
Chrome and Edge on Android, Mozilla autopush, Apple, Microsoft). The push service sees the TasmoFleet server's
address, the time and the size of each push, never its content.

Egress: the sender uses the webhook's HTTP client (ten seconds per attempt, redirects only to the same host) and,
like the webhook, ignores `HTTP_PROXY`/`HTTPS_PROXY`. Web Push therefore needs direct HTTPS egress from the
container to the push services.

Lifecycle: a subscription row ends by unsubscribe, by 404 or 410, by its owner no longer being an admin at an
event, by a VAPID key replace (W2), or by a database restore without it. The outcome columns end with the row.
There is no in-memory state; sends in flight are part of the notification drain at shutdown (5 seconds).

For #611: a browser whose subscription's `applicationServerKey` differs from `GET /settings/system/push/key` must
subscribe again (after a W2 replace the old subscription no longer exists on the server), or push stops without a
sign. The Settings list must show every admin's subscriptions with their owner and its `last_error`, and any admin
must be able to remove any of them: that is the only way to stop the pushes of an SSO or header admin who was removed
at the identity provider and never signs in again (W6).
