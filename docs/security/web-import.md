# Web import (TasmoAdmin) security notes (M2-7)

Code: `internal/importer`, `internal/web/import.go`, `internal/app/import.go`, the multipart exemption in `internal/app/guard.go`, `auth.SteppedUp/StepUp`.

| ID  | Rule                                                                                                                                                                                                              | Test |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| I1  | Admin only, checked by the route middleware before anything is parsed or read; operators get 403, anonymous requests 401. **Step-up dropped 2026-10-21** (decision "admins may do everything", audit rows 2 and 3; the earlier rule asked local admins for the password and OIDC admins for an IdP re-authentication, header principals were exempt). Reason: the import is an admin tool in a homelab; the dry-run plan with its single confirmation protects against mistakes, and a stolen admin session can already do everything else an admin can. Remaining controls: the admin role, CSRF on both routes (the multipart upload carries the token in the header, see I2), the size and parse limits (I3), the audit trail (I7), the in-memory single-use plan bound to the login session (I4), and the rule that imported credentials are never echoed back. | `TestImportIsAdminOnly`, `TestImportRoutesRefuseOperatorsAndAnonymous`, `TestImportNeedsNoStepUp` |
| I2  | Uploads never touch the disk. `guardBodies` allows multipart only on `POST /import/tasmoadmin` and only with the CSRF header (otherwise the CSRF middleware would parse the form into temp files). The handler streams parts with `multipart.Reader`. | `TestGuardBodiesAllowsMultipartOnlyForImportWithHeader` |
| I3  | 1 MiB per file, 3 MiB + framing per request, three named file fields only, content type allow-list plus byte sniffing (no zip, html, binary). The parser stops at 1000 records and 32 fields of 4 KiB per record; the plan keeps at most 50 row errors and counts the rest. No archive is ever opened.                          | `TestImportRejectsBadUploads`, `TestPlanRejectsOversizeInputs`, `TestPlanBoundsRowErrors`, `TestParseDevicesBoundsRecordsAndFields` |
| I4  | The key file and decrypted passwords live in memory only. They are not in errors, `slog` values (`Plan.LogValue`), the report, audit details or HTML. The pending plan (with passwords) is kept in memory for at most 10 minutes (a timer drops it, no further request needed), bound to the login session (not just the user), single use, at most 4; a full store refuses the new plan instead of evicting another session's. Zeroing is best effort only: Go strings, cipher state and I/O buffers cannot be wiped, so the importer clears the byte slices it owns and drops references, nothing more. | `TestSecretsNeverLeakIntoErrorsLogsOrReport`, `TestImportResponsesHideSecretsAndEscapeCells`, `TestImportPlanThenApply`, `TestPendingPlans*` |
| I5  | Cell text is data: HTML-escaped, never used in a path (backups use device ids), names with control characters are refused by inventory validation.                                                                    | `TestPathTraversalNameIsPlainTextAndSkippedRowsAreNotWritten` |
| I6  | Probes are bounded (4 in flight, 20 s each) and go through `tasmota.Client` (SSRF guard, `DEVICE_NETWORKS`). The plan itself never contacts a device.                                                              | `TestApplyBoundsProbesAndKeepsUnreachable` |
| I7  | Every device write is audited by `inventory.Upsert`; one `import.tasmoadmin` summary event is added at apply (who, counts), and one `import.tasmoadmin.plan` event at upload (who, file names without control characters, counts). Contents and passwords are never part of an entry. | `TestApplyBoundsProbesAndKeepsUnreachable`, `TestImportUploadIsAuditedWithoutSecrets` |

Residual: the apply runs inside the request; closing the browser cancels it (the report of a rerun shows merges, `Upsert` is idempotent).

## Header mode (residual risk)

**Superseded 2026-10-21.** The web import used to be off by default in `AUTH_MODE=header` (`IMPORT_WEB_HEADER_MODE`, now removed without a shim) because header principals cannot step up. With the step-up gone for everybody the import is available in every mode. Residual risk: the header-mode CSRF token is `HMAC(csrfKey, user)`, static per user and never rotated, so a hijacked or unattended browser behind the proxy can import without more proof. Put a re-authentication or MFA policy on `/import/tasmoadmin*` at the proxy if that matters. A per-session CSRF token for header mode is still only proposed.

## Preview accuracy

Rows the identity rules of `inventory.Upsert` will refuse for reasons known before the probe are shown as skipped with "will be refused" (not sent). Rules that depend on the probed MAC are enforced by `Upsert` at apply time and may still refuse a row the preview showed as merge or create; the report says so.
